# ADR-0003 — Expand one feature at a time

**Decision.** Keep Vite, the existing TypeScript picker, one Worker and one PostGIS database. The browser entry point composes independently testable features. The picker owns geographic state and exposes a read-only summary of the current selection, including manual provenance and boundary uncertainty. The reporting module requests that summary at download time. It receives neither device coordinates nor a database client.

The Worker owns HTTP validation, rate limits and the lifetime of its restricted Hyperdrive connection. The geographic resolver owns reconciliation. Keep future report intake, tracking and directory handlers in separate feature modules behind explicit routes. Add database capabilities through reviewed migrations and grants. The location reader needs no write grant to support drafts. The client can be served and tested without a paid AI or mapping service.

**Routing choice.** The picker and draft are one workflow on one URL. Adding React and a router now would increase the initial download and require a lifecycle adapter for the working DOM controller. When public cases or places first need shareable detail URLs, evaluate React Router Data Mode for nested screens, loaders and error handling with the existing Vite build. Declarative Mode suits navigation alone. Framework Mode would also take ownership of build and rendering conventions. Start any trial with one new route; keep the geographic contracts and browser suite. Verify direct links, refresh, back navigation, focus restoration and the initial transfer on a narrow mobile viewport before adopting the router.
