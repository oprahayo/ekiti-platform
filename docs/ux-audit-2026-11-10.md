# UI/UX audit — Ekiti Civic staging — 10 November 2026

## Scope and evidence

Reviewed the current GitHub implementation after PR #8 (HTML, CSS, location picker, map and report-draft controller), the staging deployment's verified API/smoke behavior, and the official Ekiti State government's descriptions of its identity. Remediation is tracked in `design/civic-mobile-first-audit`. This is an application code, interaction, and automated responsive audit; it is not a substitute for manual testing on a physical Android device and iPhone.

The platform is independent. The Ekiti State Government's 2022 public notice restricts unauthorized use of the official logo, so this redesign **does not copy or use the government logo**. The colors are **our own approximations** inspired by the emblem's visible landscape colors, not an official brand guide. References:
- https://www.ekitistate.gov.ng/archives/24737 (official seal restriction)
- https://www.ekitistate.gov.ng/archives/22493 (hills, vegetation, water, new dawn, book)
- https://www.ekitistate.gov.ng/ (government context; not a template)

## Findings and changes

| Priority | Observed issue in shipped source | User impact | Implemented correction |
| --- | --- | --- | --- |
| High | Homepage led with an oversized promotional hero and decorative orbital graphics | Tasks buried below the fold on phones; no immediate path to real functionality | Compact text-led introduction, primary area finder link, secondary private draft link |
| High | Three repeated feature cards, floating statistic panels and workflow chips | Generic template appearance; visual overload without added functionality | Removed cards, chips, circular badges and false dashboard-like panels; added editorial sections and dividers |
| High | Monochrome green identity detached from Ekiti landscape reference | Unconvincing geographic identity | New independent palette: forest, sunrise gold, water blue, restrained ribbon red and warm paper |
| High | State identity could be confused with government affiliation | Trust and legal/brand confusion | Text-only independent wordmark; explicit affiliation notice; no government seal |
| High | LGA and ward both used a redundant free-text filter plus select | Up to four controls for two simple choices | One native keyboard-friendly select per area level |
| High | Latitude/longitude fields exposed as part of the main default journey | Novices encounter technical fields before selecting an area | Precision controls under clearly labeled optional disclosure; reveal only on request |
| High | Device geolocation and server lookup relation was not clear at the entry point | Risk of uncertainty about location sharing | Consent explanation before GPS/map; coordinates sent only on explicit confirmation |
| High | Page described draft/download tools with persuasive CTA language | May be confused with live complaint submission | Explicit "download only; not submitted or tracked" in hero note, report section and footer |
| High | Breakpoint-driven desktop composition shrunk to mobile | Stacked furniture-like sections instead of small-screen-first tasks | Mobile-first CSS, enhanced into two columns only on wide displays |
| Medium | Selection summary looked like a separate promotional card | People couldn't relate it to area controls | Plain separated summary follows the selector in source order; status remains visible |
| Medium | Decorative statistics were treated as visual achievement badges | Adds little meaning and looks artificial | Simple reference counts in context, not cards |
| Medium | External design flourishes could compete with real map | More weight and distraction | Remove decorative map/3D visuals; keep MapLibre lazy-loaded |
| Medium | Primary links, native controls and collapsible tools lacked explicit viewport regression coverage | Layout/touch regressions not caught early | Playwright tests for viewport overflow from 280px–1440px and key target heights |
| Medium | Site did not yet explicitly test that marketing design introduced no third-party font requests | Privacy, performance and reliability | System font stack and browser test for same-origin initial requests |
| Pending | MapLibre JavaScript remains relatively large when opened | Loading cost on slower devices | Lazy loading retained; bundle reduction is later performance work |
| Pending | iOS Safari, Android TalkBack and 200%/400% text zoom not yet manually inspected | Unknown real-device/focus behavior | Add manual real-device accessibility gate prior to production release |

## Applied design principles

- One primary action on small screens; no card-grid navigation.
- First usable selector near the beginning of the page; not hidden inside settings.
- Honest task availability: report intake, tracking, directory search and AI chat are **not** advertised as live features.
- Warm off-white surfaces and dark legible text; no broad dark hero wall or colored marketing panels.
- Keep native controls and predictable keyboard/screen reader behavior; 44px minimum action height.
- Code doesn't load any external fonts or the heavy map until the visitor asks for it.
- Case-sensitive geographic evidence stays authoritative; ward polygons are still unverified.

## Automated acceptance checks

The Playwright suite covers widths 280, 320, 360, 375, 390, 428, 768, 1024 and 1440px; horizontal overflow, action dimensions, default-hidden precision controls, accessibility of native selects, privacy/disclosure text, initial same-origin requests, GPS opt-in, verified boundary checking, map loading, draft download privacy, and error/retry states. The GitHub `Checks` workflow additionally rebuilds a fresh PostGIS dataset and validates geographic integrity.

Only count tests as passing after the corresponding GitHub workflow reports success.

## Open decisions for next milestone

True report submission is intentionally not shipped by this redesign. Before adding personally identifiable reports and attachments, define: consent text and purposes; anonymous vs. identified report handling; moderation and escalation; retention/deletion windows; handling of false reports and threats; agency status confirmation rules; evidence visibility; abuse prevention; and authorized access boundaries. A download-only staging tool must not be rebranded as an active emergency service.
